# 함께 · 가족 포트폴리오

두 사람이 각자의 아이폰에서 가족 자산을 함께 조회하고, 본인 계좌의 거래를 기록하는 한국어 웹앱입니다. Node.js 기본 HTTP 서버와 SQLite를 사용하며 앱 실행에 외부 npm 의존성은 없습니다.

실사용 배포 방식은 **GitHub Pages + Supabase**로 준비되어 있습니다. 정적 앱은 GitHub Pages에서, 인증과 공동 자산 저장은 Supabase에서 처리합니다. [단계별 배포 안내](supabase/README.md)를 따르세요. 아래 자체 Node 서버 설명은 로컬 개발 및 대안 구성을 위한 안내입니다. 테스트에는 PostgreSQL 엔진인 PGlite 개발 의존성이 필요하므로 `npm ci`로 설치합니다.

## 현재 준비된 기능

- 가족/개인별 총자산, 보유분 평가손익, 현금, 종목 비중
- 계좌 필터, 종목 검색, 기존 거래 조회, 본인 계좌의 매수·매도·입출금 기록
- 공동 시세/환율 수동 갱신, 가족 자산추이 조회, 오늘의 총자산 기록
- 두 개의 개별 계정, 해시 비밀번호, 서버 세션, 변경 충돌 감지
- 15초 간격 공동 데이터 갱신, JSON 데이터 내보내기
- 아이폰 화면에 맞춘 하단 메뉴와 홈 화면 추가용 웹앱 매니페스트

## 로컬 실행

Node.js 22.13 이상이 필요합니다(이 환경에서 Node.js 24.19로 검증). 이 작업 공간은 이미 격리되어 있으므로 기존 `/workspace/portfolio` 체크아웃을 사용하고 별도 worktree를 만들지 않습니다.

```sh
cd /workspace/portfolio
npm run check
npm test
npm start
```

기본 주소는 루프백 포트 3000입니다. 서버는 기본적으로 `/workspace/portfolio-data/seed.json`으로 초기 SQLite DB를 생성합니다. 현재 첨부 데이터는 이 비공개 디렉터리에 준비되어 있습니다. 최초 실행 화면에서 **엑셀에 있는 두 소유자의 정확한 이름**과 각자의 비밀번호(10~128자)를 지정한 뒤 로그인합니다. 계정 생성은 최초 한 번, HTTPS 외부 배포 전 로컬 접속에서만 허용됩니다. 실제 비밀번호는 코드, 채팅, 로그에 넣지 마세요.

`DATA_DIR`, `SEED_FILE`, `PORT`, `HOST`, `SECURE_COOKIE`를 환경변수로 설정할 수 있습니다. `DATA_DIR`에는 초기 데이터, DB, 사용자와 세션이 저장됩니다. 개인 엑셀, seed, DB, 백업을 Git에 올리지 마세요. 정적 `public` 디렉터리에 복사하지 마세요.

## 엑셀에서 초기 데이터 만들기

현재 데이터는 이미 준비되어 있습니다. 다른 새 설치에서만 아래 절차를 사용합니다. Python과 `openpyxl`이 필요하며 앱 실행 시에는 필요하지 않습니다. `통합_거래내역`, `통합_자산현황_최종`, `자산추이` 시트의 현재 형식만 지원합니다.

```sh
python scripts/import_excel.py '/private/path/자산 포트폴리오.xlsx' '/private/data/seed.json'
DATA_DIR=/private/data npm start
```

가져오기는 계산된 캐시 값을 사용합니다. 기존 파일을 덮어쓰지 않으며 이미 생성된 DB에 자동 병합하지 않습니다. 실행 중 DB를 삭제하거나 재가져오기로 대체하지 마세요. 원본 보유자산 합계와 원본 자산추이의 마지막 값은 서로 다르므로 그대로 보존합니다. 원본 거래에는 날짜가 없어서 날짜를 만들어 넣지 않습니다.

초기 평균단가는 원본 평가수익률에서 역산해 원본과 같은 보유분 평가수익률을 표시합니다. 이후 매수는 이동평균, 매도는 남은 평균단가 유지 방식입니다. 초기 거래 100건을 다시 잔고에 적용하지 않습니다. 과거 실현손익이나 세금 신고 계산을 제공하지 않으며, 원본의 평균단가 계산 방식 자체도 감사된 투자 성과가 아닙니다. 해외자산의 원화 평가손익은 현재 입력 환율로 환산한 보유분 단순 평가손익입니다.

새 거래는 오늘(한국시간)의 본인 기존 계좌에 입력하며, 해외 매수/매도도 거래 당시 입력한 환율로 **원화 현금**에 반영합니다. 수수료·세금도 국내 티커는 원화, 해외 티커는 달러로 입력하며, 해외 수수료는 거래 환율로 원화 환산해 매수 시 차감액에 더하고 매도 시 입금액에서 뺍니다. 새 기록에는 입력 수수료 통화와 원화 환산액을 함께 저장합니다. 기존 저장 거래 금액은 재계산하지 않습니다. 외화 예수금, 공매도, 주문 실행/증권사 연동은 지원하지 않습니다. 잔고 부족 시 먼저 입금을 기록하세요. 새 종목은 티커(국내는 `KRX:6자리`)와 종목명을 입력할 수 있습니다. 기록 수정·삭제 UI는 제공하지 않으므로 저장 전에 확인하세요. 잘못된 거래는 반대 거래를 오늘 기록해 정정할 수 있으나 최초 기록도 보존됩니다.

## 두 아이폰에서 실제 사용하기

현재 검증은 개발 환경 내부에서만 수행합니다. 외부 배포와 실제 아이폰 Safari 검증은 별도 단계입니다.

1. 로컬 상태에서 두 계정을 먼저 만들고 로그인을 확인합니다.
2. Node.js 프로세스를 실행할 서버와 영속 디스크를 준비합니다. 두 아이폰은 **같은 서버 주소**를 사용해야 합니다. 정적 사이트 호스팅만으로는 동작하지 않습니다.
3. 개인 데이터 디렉터리를 영속 디스크에 안전하게 이전합니다. 실행 중 DB 복사는 피하고 서버를 정지한 상태에서 DB 및 관련 WAL/SHM 파일을 함께 백업하거나 SQLite의 일관된 백업 기능을 사용합니다. JSON 내보내기는 자산 데이터만 포함하며 계정과 세션을 복구하는 DB 백업을 대체하지 않습니다.
4. HTTPS 리버스 프록시 뒤에서 `HOST=0.0.0.0 SECURE_COOKIE=1 DATA_DIR=/persistent/private-data npm start`로 실행합니다. Node 포트는 프록시에서만 접근하도록 제한합니다. Host/Origin 헤더를 보존하고 TLS 인증서를 정상 설정하세요. 계정 설정을 마치기 전 서버를 외부에 공개하지 마세요.
5. 두 아이폰의 Safari에서 HTTPS 주소를 열고 각자 로그인합니다. 공유 메뉴의 **홈 화면에 추가**를 선택합니다. 다른 기기의 변경은 최대 약 15초 후 반영되며 새로고침 버튼으로 즉시 조회할 수 있습니다.

앱은 온라인 연결을 필요로 합니다. 금융 데이터를 브라우저 오프라인 캐시에 보관하지 않으며, 실시간 시세와 Google Sheets 양방향 동기화는 아직 연결되어 있지 않습니다. 가격/환율은 설정에서 직접 입력합니다. 운영 전 백업/복구, 계정 복구 절차, 서버 접근 제어를 준비하세요. 비밀번호 변경/재설정 UI는 아직 없습니다.

## 검증

`npm test`는 환산·평균단가·현금·잔고 검증과 서버의 두 계정 인증, 공동 조회, 본인 거래 제한, 동시 수정 충돌, 시세 변경, 일자별 기록, DB 재시작 후 영속성, 로그아웃, 인증 없는 백업 차단을 확인합니다. 테스트는 임시 합성 데이터만 사용하고 실제 자산 DB를 수정하지 않습니다.

## 채팅의 웹 미리보기

일반 서버 화면인 `public/index.html`은 별도의 JS/CSS 및 인증 API를 필요로 하므로 HTML만 표시하는 웹 미리보기에서 직접 실행할 수 없습니다. 독립형 미리보기는 아래 명령으로 생성합니다.

```sh
node scripts/build-preview.js /workspace/portfolio-data/seed.json
```

생성된 `preview.html`은 스타일, 스크립트, 선택한 초기 데이터를 모두 담습니다. 서버 없이 샌드박스 iframe에서도 화면·탭·입력·시세 관리 등을 체험할 수 있으며, 모든 변경은 해당 화면의 메모리에만 적용됩니다. 다시 열면 초기화되고 두 기기 사이에 동기화되지 않습니다. 상단에 체험용임을 표시하며 사용자 전환은 실제 로그인이 아닙니다.

**이 파일에는 개인 자산 데이터가 포함됩니다.** Git에서 제외되어 있고 앱 서버가 제공하지도 않습니다. 공개 호스팅하거나 저장소에 추가하지 마세요. 실제 공동 사용은 인증 서버와 HTTPS 배포 절차를 따릅니다.
